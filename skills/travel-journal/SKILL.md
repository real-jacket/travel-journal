# 山野取景 · 新增旅行

把新旅行接入既有网站，保留旧路书和暖纸色、深绿的摄影杂志风。访客页面只呈现旅行所需信息；研究和技术说明放在开发记录。

## 定位与范围

先读仓库的 `AGENTS.md`、`README.md` 与 [新增旅行流程](../../docs/add-a-trip.md)。本技能的维护副本位于仓库 `skills/travel-journal/`，解析 `SKILL.md` 的真实文件路径后，上两级是项目根；本地技能入口可能是指向此目录的符号链接。

检查当前 Git 状态、旅行清单和实际源文件，保留无关改动。用户可能从零规划，也可能提供已经制作好的 HTML；按本次需求处理，不把旧旅行的日期、天数、酒店或费用复制成新事实。

## 执行

1. 从本次描述提取目的地、出发地、日期窗口、完整天数/晚数、人数、交通、预算与拍摄重点。缺少会改变路线的事实时只询问必要信息；其他可独立工作继续推进。
2. 在项目根执行 `npm run trip:new -- <slug>`，创建 `work/trips/<slug>/brief.md` 和 `entry.json`。已有 ID、目录或草稿不覆盖，继续编辑原草稿。草稿不发布。
3. 新计划按 [需求与来源模板](../../templates/trip-brief.md) 研究；已有路书先核本地依赖与原作出处。小红书、抖音、B站有工具可用时搜摄影师本人经典作品，并与文旅、景区、气象、运营方和吃住资料交叉核对。无法完整读取时保留具体边界，不伪造已观看或精确机位。
4. 制作或迁入 `public/trips/<slug>/index.html`，保留运行必需的相对资产与照片署名。加入桌面、手机都可见的 `href="../../"` 返回首页入口。不要复制私有地图配置、平台临时签名或整个研究目录。
5. 填完 [入口字段模板](../../templates/trip-entry.json)，加入 `src/data/trips.js`。封面放在 `public/images/`，扩展名与实际格式一致；署名必填，本人照片的 `imageSource` 可为空。首页自动选首个 `planned`，没有则选首项；将新计划放在其他计划中项之前即可推荐，不为新旅行改首页组件。
6. 执行 `npm run check`。用实际浏览器核对桌面和390px手机：搜索/状态/无结果恢复、首页→新路书→首页、图片与地图等本次核心操作。测试通过不能替代运行和视觉证据。
7. 若本次用户已要求上传或上线，按授权范围提交精确文件并推送；等待该 commit 的 Pages 工作流成功，打开公网首页与新路书验证。仅要求草稿或本地接入时，交付该范围的实际结果。

## 旅行内容标准

- 拍摄参考选择能学习构图的本人作品，明确地点、地面/平台/岸边/航拍视角和可进入方式。原作拍摄日、发布日期、原EXIF与本路书参数建议分开；成片后期、叶色与雾的未知情况标清。署名和原帖不是自动转载授权。
- 地图集中显示地形、水体、城市乡镇、路网和日程路线；详细机位信息放在侧栏，避免与地图弹窗重复。真实道路轨迹与方向示意分别标清，停车入口与景区参考中心不能混用。
- 日程给交通、吃饭、睡眠和停拍留时间；电车旅行使用本次实测续航与电池信息安排补能。住宿逐晚匹配下一处机位；历史设施/消费与当前可用性/预算分开。
- 候选计划用 `planned`；历史路书用 `archived`，不因日期已过声称旅行实际完成。

## 交付

说明新增或更新了什么、可用入口、检查证据，以及当天现场信息、网络依赖或图像许可的具体未核实项。标准流程不授予未来任意旅行的发布权限，也不新增后台、账号或数据库。
