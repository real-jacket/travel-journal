# 山野取景 · 加入首页

首页只是入口，每趟旅行在自己的站点，首页读取 `trip.json` 收录。本技能只处理“加入首页”；制作完整路书（调研、地图、行程）使用 `real-jacket/trip-template` 仓库自带的 travel-journal 技能。

## 定位

先读仓库的 `AGENTS.md`、`README.md`、[新增旅行流程](../../docs/add-a-trip.md) 与 [旅行清单规范](../../docs/trip-spec.md)。检查 Git 状态，保留无关改动。

## 执行分工

协调者（主模型）负责需求分析、计划、设计决策和独立最终验收；执行委派给用户指定的 Sonnet 5.5 子代理，推理强度 high，分派时写明目标文件、预期行为与验收证据。执行者自报不能替代协调者验收，发布遵守当前授权。细则见 [SOP 的执行分工](../../docs/add-a-trip.md#执行分工)。

## 执行

1. 判断路线：要做完整路书，用 `gh repo create <name> --template real-jacket/trip-template --public --clone` 并交给模板的技能；已有页面或文章，则只需托管一份 `trip.json`，用可选 `url` 指向它。
2. 按 [规范](../../docs/trip-spec.md) 核对字段：`imageCredit` 必填，所有地址为 https，封面可匿名访问。不把旧旅行的日期、天数或酒店复制成新事实。
3. 在本仓库的 `trips.json` 增加清单地址（一行），不改首页组件、文案或测试。
4. 运行 `pnpm check`（先同步并校验全部清单；本机经代理时加 `NODE_USE_ENV_PROXY=1`）。用实际浏览器核对 1280px 与 390px：新卡片封面、搜索与无结果恢复、链接打开路书并能回首页、无横向溢出。测试通过不能替代运行与视觉证据。
5. 只有用户本次要求提交、推送或发布时才执行，范围以授权为准；等待 Pages 工作流成功并打开公网首页验证。

## 交付

说明加入了什么、清单地址、检查证据，以及未核实项（图像许可、网络依赖等）。标准流程不授予未来任意旅行的发布权限，也不新增后台、账号或数据库。
