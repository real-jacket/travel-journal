# 新增一份旅行路书

本流程用于把新的摄影旅行计划加入“山野取景”，也适用于接入已经做好的路书。以下路径均相对项目根目录；研究草稿留在 `work/`，访客只看到旅行内容。

## 执行分工

协调者负责需求与路线、设计决策、计划与任务拆解，以及独立最终验收。协调者同时负责分析与审核；实际执行交给用户指定的 Sonnet 5.5 子代理（high effort），分派时明确目标文件、预期行为与验收证据。执行者提交实际产物和检查结果，不能以自报成功代替协调者验收。发布仍遵守用户当前授权。

## 1. 开一份草稿

在项目根目录运行：

```sh
pnpm trip:new yunnan-2027
```

将示例替换为本次旅行的唯一 slug。slug 使用小写字母、数字、连字符；已有项目 ID 或目标目录会被拒绝，避免覆盖旧旅行。

命令只创建被 Git 忽略的 `work/trips/<slug>/brief.md` 和 `entry.json`，不会接入首页或发布网站。先填写 brief；生成的 entry 是填写提示，不是可直接上线的事实。

## 2. 把旅行需求说清楚

确认出发地、可用天数、日期窗口、同行人数、驾驶方式、摄影题材和预算。电车填写实测高速续航、电池电量与补能习惯；时间尚未确定时保留候选日期。

按 [需求模板](../templates/trip-brief.md) 填写，也可直接把需求交给 Claude Code 或 Codex。不要默认沿用皖南的四天、路线、桩数、酒店、物候或预算。

一份可执行路书至少包含：

- 每天的路线、驾驶预算、吃饭、休息和住宿；往返交通也计入天数。
- 经典拍摄地点与专业成片、停车与步行入口、建议光线窗口、构图和设备建议。
- 一张整合地形、水体、城市/乡镇、道路与每天路线的地图。
- 沿途餐饮、逐晚住宿、补能节奏、费用口径和出发前复核事项。

## 3. 研究并留下可追溯资料

小红书、抖音、B站调研走 agent-reach，查法、降级、落盘与台账规则全部在 [调研手册](../skills/travel-journal/references/research.md)：开工先跑 `agent-reach doctor --json`，原始资料放 `work/trips/<slug>/research/`，台账用 [brief 模板](../templates/trip-brief.md) 的“来源台账”表，链接用规范化形式（不含 `xsec_token`）。再与当地文旅、景区、气象、道路/充电运营方、酒店和餐厅资料交叉核对。公开路书只呈现读者需要的署名、出处与必要不确定性。

- 日期没有证据就写“未标”；发布日、拍摄日、生效日分开。旧实拍不代表当季叶量，旧酒店设施不代表当天有房或可充电。
- 搜索摘要、封面与完整原图分别标清；不声称看过未实际观看的视频，不把推荐列表里的其他作品当作所开视频的内容。

### 选择可以参考拍摄的经典成片

- 优先作者本人风光或旅拍作品，有明确地点、完整画面和原作入口；从公开作品系列判断其构图能力，不凭名称断言职业资格。
- 选择能读出前景、中景、远景、光线、尺度和画面组织的作品，不用随手记录照补数量。
- 作者指定图序时逐张对应地点；地面、观景台、岸边、游船和航拍视角要分开，不把航拍图当作地面可复刻机位。
- 图旁写作者、原帖、地点、拍摄日/发布日期、建议到位时间和复现技巧。原作未给EXIF时，建议参数明确为本路书分析，不伪装成作者参数。
- 后期处理过的树色、水面、天空等说明为成片参考；不得据此保证现场有雾、叶色或特定前景。
- 发布副本保留署名。本人照片注明本人摄影；第三方图片核对可用许可或作者授权，来源链接本身不构成转载许可。

### 地图和机位

每份路书用一张整合地图：地形、水体、城镇、分级道路和按天切换的真实道路路线（不用直线示意冒充驾车路线）。方案是 MapLibre + 同源 PMTiles 底图 + 地形，路线在制作时用 OSRM 生成，导航通过高德/百度深链，依据见 [地图选型](map-selection.md)。共用模块在 `public/vendor/map/`，用 `pnpm map:build` 生成该趟的底图与路线数据。

底图是土地覆盖地形图：森林、灌草、农田、城镇、水体/湿地、裸地用不同颜色区分，上面叠浅山体阴影，再叠分级道路（含 G/S 编号）和省/市/县界与地名；国界与争议线不画。页面用 `TripMap.renderLegend` 放一个中文图例。

制作步骤（配置写在 `scripts/maps/<slug>.json`，草稿期也可放 `work/trips/<slug>/map.json`；字段说明在 `scripts/build-trip-map.mjs` 文件头）：

```sh
pnpm map:build <slug> --routes             # OSRM 生成 routes.geojson；出现 WARNING 就把途经点挪到主路上
pnpm map:build <slug> --extract --dry-run  # 先看底图/地形体积
pnpm map:build <slug> --extract            # 生成 base.pmtiles 与 terrain.pmtiles（需要 pmtiles CLI）
pnpm map:build <slug> --landcover          # 由 ESA WorldCover 生成 landcover.pmtiles（需要 uv）
pnpm map:build <slug> --validate           # 复用旧路线时，只检查回头路
```

低缩放层用大范围、高缩放层只覆盖路线走廊和点位，避免概览出现纸色空白；页面 `maxBounds` 不超出已制作范围。每趟 `map/` 合计不超过 40 MB（测试强制）；重生成的二进制会永久留在 Git 历史里，定稿后别反复重建。

地图下方保留“用高德查看路线”分段清单：按当前方案/天把相邻点位切成“起点 → 途经 → 终点”段，每段一个高德驾车导航链接（坐标转 GCJ-02）。画出的路线用来看，分段导航用来走，两者都要有。

点击地图点位只定位并更新侧栏；成片、导航名称、入口和技巧集中在侧栏，不再做地图 popup。点位说明区分停车入口、步行目的地和大致摄影片区。技术接口、坐标转换和密钥说明不写进访客页面。

### 自驾、补能、吃住与费用

驾驶时间加上快充、排队、午饭、会车、停车、步行与休息；不要用自由流车程填满拍摄日。长山路尽量安排白天，早晚好光附近住一晚；驾驶者疲劳时可删掉可选点。

电车用本次车型和相近温度/车速下实测续航。记录起步电量、最低到站电量、公共站及备选、住宿充电类型/接口/开放条件；存在桩不等于可用。费用写清一车几人、房间数、餐费按人或按桌、电价和里程余量，历史消费与当前预算分开。

住宿逐晚匹配第二天机位，核停车到房间/岸边距离、清晨出门、早餐时段、取消条件。餐厅列具体候选、代表菜和来源；营业、鱼的计价、菜单及房量按临近行程再查。

## 4. 制作并接入

1. 完成 `public/trips/<slug>/index.html`，只复制运行必需的本地图像、脚本和样式，保持相对路径可运行。
2. 路书加上桌面与手机均可见的 `href="../../"`“回旅行首页”，原地图、照片、清单与存储容错保持可用。
3. 封面放入 `public/images/`，建议 `<slug>.webp`；扩展名必须符合实际文件格式，不能只把JPEG文件改名为WebP。
4. 填完 `work/trips/<slug>/entry.json` 后，作为对象加入 `src/data/trips.js` 的 `trips` 数组，不把未填写提示或整份JSON文件当线上内容。

| 字段 | 填写规则 |
|---|---|
| `id`、`path` | 唯一slug；`path`为`trips/<slug>/`，不带站点根目录 |
| `title`、`subtitle`、`region` | 真实旅行名、简短表达、目的地片区 |
| `status`、`statusLabel` | `planned` / “计划中”或`archived` / “历史路书”；日期已过不等于旅行完成 |
| `date`、`dateNote`、`duration` | 日期以四位年份开头，如`2027.03.12 — 03.15`；明确候选/已定口径及完整天数与晚数 |
| `transport`、`route`、`description`、`tags` | 出发/驾驶方式、至少两个地点的非空字符串数组、概述、至少一个题材的非空字符串数组 |
| `image`、`imageAlt`、`imageCredit`、`imageSource` | `public/`内封面相对路径、图像描述、必填署名、原作链接；`imageSource`可为空字符串表示本人照片 |
| `highlights` | 路书实际具备的内容，如每日路线、机位、吃住和补能 |

首页主推第一个 `planned` 项；没有计划中项目时显示首项。要主推新计划，将其放在其他 `planned` 前面，或确认旧计划确实归档后改为 `archived`。仅增加清单与资产即可；不需要为新项目改 App、首页或测试。

清单至少保留一项。新增时不清空已有路书；草稿未完成时留在 `work/`，不提前塞进公开清单。

## 5. 检查与验收

```sh
pnpm check
pnpm preview --host 127.0.0.1 --port 4180 --strictPort
```

`check` 依次运行测试（含 Markdown 相对链接检查）、构建与构建契约检查。开发服务（`pnpm dev`）已能直接打开 `/travel-journal/trips/<slug>/`；最终仍用预览核对构建后的相对资源。

- 1280px桌面与390px手机：标题、图片、控件可读，无横向溢出，主操作触摸区域可用。
- 首页→新路书→首页实际点击完成；新项目可按目的地/题材搜索，状态筛选和无结果恢复正常。
- 照片加载、放大/关闭、日期/行程选择、地图缩放与按天路线、点位侧栏、已有清单等核心交互实际可用。
- 新封面和完整路书的事实、日期、状态、作者、地点一致，所有必需相对资产都能打开。
- 公开文件不含私有地图配置、平台临时签名、token、`/Users/`或本地服务路径。对无证据事项保留明确边界。
- 交付记录包含需求brief、资料台账、完整路书、封面与署名、清单项、检查结果及真实浏览器截图。

测试通过不是地图或视觉验证。第三方地图/平台链接受网络影响；出发前仍要复核路况、物候、住处和桩况。

## 6. 提交和发布

用户本次已要求上传或上线时，按该次授权范围提交到目标仓库。先查看Git状态，选择本次文件并检查暂存差异，不提交 `work/`、密钥或研究缓存。

`main`推送触发当前GitHub Pages工作流。等待对应commit的Actions完成，再打开公开首页与新路书，验证图像、搜索、往返导航并核对发布内容。部署成功与网站可用分别确认；返回仓库、网站URL和验证边界。

本流程和技能不会为未来任意计划提供空白发布授权。若本次仅要求整理草稿或本地接入，就交付已验证的本地结果，后续发布按用户当次要求继续。
